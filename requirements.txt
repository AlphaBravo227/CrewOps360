# ── Python version ──────────────────────────────────────────────────────────
#
# This app runs on Python 3.11, 3.12 or 3.13. Not 3.14 or newer.
#
# That ceiling is a hard incompatibility, not caution. The `altair<6` cap below
# pins production's Altair line; altair 5.5.0 is the FINAL 5.x release (the
# index goes 5.5.0 -> 6.0.0, nothing after), and its generated schema assumes
# PEP 728's `closed=` TypedDict argument landed in Python 3.14. It did not. So
# on 3.14+ `import altair` dies with
#
#     TypeError: _TypedDictMeta.__new__() got an unexpected keyword argument 'closed'
#
# before a line of app code runs, and no package upgrade fixes it — the 5.x line
# is closed. `altair<6` and "current Python" are now permanently exclusive.
#
# The durable way out is to move production and local to altair 6 together and
# drop the cap; altair 6 supports 3.10 through 3.14. Until then, 3.13.
#
# .python-version records the preferred version, and scripts/check_python.py is
# the single source of truth the launchers check before building a venv:
#
#     python scripts/check_python.py
#
# ── Dependency bounds ───────────────────────────────────────────────────────
#
# Upper bounds on everything, so a redeploy can never silently resolve onto an
# untested major version. This is not theoretical: with `altair>=4.0.0` and no
# cap, the deployed app ended up on Altair 5.x (it emits Vega-Lite v5.20.1
# specs) while local dev resolved to Altair 6.2.2 (Vega-Lite v6.4.1). The two
# render charts through different code paths, and a whole class of blank-chart
# bugs was invisible locally as a result — see the 2026-08-15 chart fixes in
# modules/track_bidding.py.
#
# The bounds below are deliberately chosen not to move anything that is
# currently installed; they only block the next major. altair is capped below 6
# because 5.x is what production runs and 6.x is untested against this app.
#
# streamlit is left on its existing range because the deployed version is older
# than local and is not exposed to the client, so an exact pin can't be
# determined from outside. To tighten it, read the version from the Streamlit
# Cloud build log ("Successfully installed ... streamlit-X.Y.Z") and pin to it.
#
# These are ranges, not a lockfile, so they prevent drift onto an untested
# major but do not make builds reproducible. A lockfile plus the pinned Python
# version is what would actually guarantee local behaves like production.

streamlit>=1.28.0,<2.0.0
pandas>=2.1.0,<4.0.0
numpy>=1.26.0,<3.0.0
openpyxl>=3.1.0,<4.0.0
xlrd>=2.0.1,<3.0.0
python-dateutil>=2.8.0,<3.0.0
pytz>=2023.3
altair>=5.0.0,!=5.4.0,!=5.4.1,<6.0.0
# altair 5.x reads TypedDict(closed=) from here on Python < 3.14; 4.13 is
# the first release that has it. Without a floor, an old one reproduces the
# same TypeError on an otherwise supported Python.
typing_extensions>=4.13,<5.0.0
setuptools>=68.0.0,<90.0.0
matplotlib>=3.8.0,<4.0.0
seaborn>=0.13.0,<0.14.0
fpdf2>=2.8.0,<3.0.0
icalendar>=5.0.0,<8.0.0
xlsxwriter>=3.1.0,<4.0.0
